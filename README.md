#  ✷ Durian Desktop 💻

A native desktop app for [Durian](https://github.com/gguf-org/durian) — the self-improving fruit that runs in your terminal and messaging platforms.

Built with [Tauri 2](https://v2.tauri.app/) (Rust + React/TypeScript).

## Features

- Chat interface with streaming responses and real-time tool activity
- Live action status bar showing file reads/writes, terminal commands, browser navigation, etc.
- Collapsible step-by-step activity log after each response
- Workspace/file explorer with auto-refresh
- Session management with persistent history
- Multiple LLM provider support (OpenRouter, Anthropic, OpenAI, local models, 15+ more)
- Dark and light themes
- Native folder picker for workspace selection

## Prerequisites

- [Node.js](https://nodejs.org/) >= 18
- [Rust](https://www.rust-lang.org/tools/install) >= 1.77
- [Durian](https://durian.gguf.org) installed and in PATH (auto detection in the recent version)
- Windows: WebView2 (bundled with Windows 11, install separately on Windows 10)
- Linux: `libwebkit2gtk-4.1-dev` and related GTK/WebKit packages

## Architecture

### How it works

1. The user types a query in the React frontend
2. The frontend calls `invoke('run_durian_query')` which spawns `durian chat -q "..." -Q --source desktop` as a subprocess
3. Stdout is streamed back via Tauri's `durian-output` event
4. A separate watcher thread monitors durian's session JSON file for tool activity (file reads, terminal commands, etc.)
5. Tool activities are emitted as `durian-activity` events with categorized action types (read/write/terminal/search/browser) and paths
6. The MessageBubble component shows a live status bar during streaming, then a collapsible activity log after completion

### Tool activity display

The app provides two views of agent activity:

- **Live status bar** (during streaming): A compact bar above the response showing the current action with icon, pulsing indicator, and the file path/command/URL being operated on (e.g., "Reading src/App.tsx")
- **Completed activity drawer** (after streaming): A collapsed summary below the response (e.g., "5 steps: 2 reads, 1 write, 1 terminal") that expands to show each step with action verb and path

### Settings

Settings (provider, API key, model, endpoint, toolsets, workspaces) are persisted to `settings.json` in the Tauri app data directory. API keys are also written to durian's `config.yaml` so the CLI subprocess picks them up.

## Configuration

### Durian ✷

Make sure `durian` is installed and accessible:

```bash
# Install durian
curl -fsSL https://raw.githubusercontent.com/gguf-org/durian/main/scripts/install.sh | bash

# Verify
durian --version
```

For Windows PowerShell

```bash
irm https://raw.githubusercontent.com/gguf-org/durian/main/scripts/install.ps1 | iex
```

### Supported Providers

The app supports all durian providers. Set your provider and API key in Settings:

| Provider | Setup |
|----------|-------|
| Ollama | No key needed (local) |
| LM Studio | No key needed (local) |
| vLLM | No key needed (local) |
| OpenRouter | API key |
| Anthropic | API key |
| OpenAI | API key |
| Google Gemini | API key |

And 10+ more. See the [full provider list via the documentation](https://durian.gguf.org).
